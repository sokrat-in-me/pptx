# Git и публикация изменений

Обязательные правила для агентов и разработчиков этого репозитория.

## 1. Всегда пушить обновления

После **любых** изменений в коде, данных или сгенерированных файлах презентаций:

1. **Закоммитить** все релевантные файлы с понятным сообщением на русском или английском.
2. **Запушить** ветку на `origin` командой:
   ```bash
   git push -u origin <имя-ветки>
   ```
3. **Не завершать задачу**, пока `git status` не показывает:
   - `nothing to commit, working tree clean`
   - ветка синхронизирована с `origin` (`Your branch is up to date with 'origin/...'`)

Если push не удался из‑за сети — повторить до 4 раз с экспоненциальной задержкой (4с, 8с, 16с, 32с).

## 2. Когда коммитить и пушить

| Ситуация | Действие |
|----------|----------|
| Изменён генератор (`generate_*.py`, `themes/`) | коммит + push |
| Пересобрана презентация (`.pptx`) | коммит + push вместе с кодом |
| Обновлены данные (`data/*.csv`) | коммит + push |
| Обновлены правила (`ai/rules/`) | коммит + push |
| Исправление по запросу пользователя | коммит + push **в том же ходе**, до ответа пользователю |

**Не оставлять** незакоммиченные или незапушенные изменения «на потом».

## 3. Ветки

- Рабочие ветки: `cursor/<описание>-<суффикс>` (например `cursor/rtr-launch-schedule-presentation-89d9`).
- Базовая ветка для PR: `main`.
- Одна ветка — один PR; при продолжении задачи использовать ту же ветку.

## 4. Pull Request

- Создать или обновить PR **после push**, если в задаче были изменения кода.
- Перед итоговым ответом пользователю убедиться, что PR отражает последний коммит на `origin`.

## 5. Чеклист перед завершением задачи

- [ ] Все изменения закоммичены
- [ ] Ветка запушена на `origin`
- [ ] Сгенерированные `.pptx` (если менялись) включены в коммит
- [ ] PR создан или обновлён
- [ ] В ответе пользователю указано, что изменения запушены (если применимо)
